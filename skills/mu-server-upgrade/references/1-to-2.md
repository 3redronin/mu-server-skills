# Upgrade Mu Server 1.x to 2.x

The major compatibility boundary in the [official 2.0.0 upgrade notes](https://muserver.io/changelog#2.0.0) is Jakarta REST. Mu Server 1.x uses JAX-RS 2.1 under `javax.ws.rs`; Mu Server 2.x uses Jakarta REST 3.0 under `jakarta.ws.rs`. The Mu Server coordinates remain `io.muserver:mu-server`, and version 2 still supports Java 8 or later.

## Migrate the whole JAX-RS ecosystem

Search application source, tests, generated source inputs, build files, configuration, and separately-built shared modules:

```text
javax.ws.rs
javax.ws.rs-api
com.fasterxml.jackson.jaxrs
jackson-jaxrs-json-provider
```

Change every JAX-RS use from `javax.ws.rs` to `jakarta.ws.rs`, including resource annotations, `core` types such as `Response`, `UriInfo`, and `MediaType`, container filters, exception mappers, readers and writers, parameter converters, interceptors, security context, SSE types, test fixtures, and mocks. Limit the namespace migration to JAX-RS; unrelated `javax.*` APIs do not move merely because Mu Server changed.

Remove an explicit `javax.ws.rs:javax.ws.rs-api` dependency if it only duplicated Mu Server's API. Mu Server 2 supplies `jakarta.ws.rs:jakarta.ws.rs-api` transitively. Keeping both APIs can allow compilation while leaving annotations or providers invisible to Mu Server, so inspect the resolved graph rather than treating a successful compile as proof.

Every external provider must also be built for `jakarta.ws.rs`. The old Jackson artifact `com.fasterxml.jackson.jaxrs:jackson-jaxrs-json-provider` is a `javax` provider and must be replaced; update its `JacksonJsonProvider` import as well. For an application staying on Jackson 2, use the matching `com.fasterxml.jackson.jakarta.rs:jackson-jakarta-rs-json-provider` release and the `com.fasterxml.jackson.jakarta.rs.json.JacksonJsonProvider` class. The current Mu Server documentation uses Jackson 3's `tools.jackson.jakarta.rs:jackson-jakarta-rs-json-provider`, which requires Java 17. Select the provider generation and release compatible with the application's chosen Java and other Jackson modules.

Rebuild shared libraries that contain resources or providers. A stale jar compiled against `javax.ws.rs` can survive a clean application-source migration.

## Diagnose the common failures

- `package javax.ws.rs does not exist`: a source, generated source, or test import has not moved.
- `ResourceClass` reports that a class contains an old JAX-RS implementation: a resource or one of its annotations was compiled against `javax.ws.rs`; locate the supplying jar and rebuild or replace it.
- A route, filter, mapper, reader, or writer silently stops applying: look for both API generations or a provider compiled against the old namespace.
- JSON returns a missing-writer or missing-reader response: confirm the Jakarta provider artifact, its updated class import, and explicit registration on `RestHandlerBuilder`.

The resource lifecycle does not become container-managed in version 2. Continue constructing and registering singleton resource and provider instances as the application did in version 1.

## Later 2.x checkpoints

When the target is newer than 2.0, also read the intervening entries. Two changes deserve explicit attention:

- From 2.1.9, a `WebApplicationException` thrown by a JAX-RS `ParamConverter` is propagated to the client instead of always becoming `400`.
- Version 2.2.10 inadvertently changed the maximum concurrent HTTP/2 streams per connection from unlimited to `100`. Version 2.3.2 makes the setting explicit through `Http2ConfigBuilder.withMaxConcurrentStreams(...)`, with a default of `200`. Set and load-test an intentional value when clients multiplex heavily over one connection.

## Focused verification

Compile every module and run live requests that cover resource matching, path and query parameters, both JSON directions, custom filters and exception mappers, and any SSE endpoints. Inspect the final dependency graph for `javax.ws.rs-api`, old Jackson JAX-RS providers, and stale shared modules. A non-JAX-RS application may need only the Mu Server version change plus its normal HTTP regression suite.
